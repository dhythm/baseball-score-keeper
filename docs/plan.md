## 1. 現状評価（サマリー）

### 資産として残す価値が高いもの

| 資産 | 評価 |
|---|---|
| **PRD**（docs/prd.md） | 要求・データモデル・ルールが具体的で、そのまま設計の基準にできる |
| **UI コンポーネント群**（components/） | モバイルファーストで作り込み済み。bottom sheet 入力、セーフエリア対応、sticky 打順表、進塁シートのプレビュー等は再利用価値が高い |
| **スコアブック記法**（"遊ゴロ"・"盗2"・"WP·2→3" 等の生成ロジック） | ドメイン知識の蓄積。仕様として抽出する価値あり |
| **イベントソーシングの方針** | `events[]` を真実のソースとする設計方針自体は正しい |

### 根本的に作り直すべきもの

**ドメイン層（lib/）はイベントソーシングが不徹底で、これが主要バグの共通原因になっている。**

- `GameEvent` に導出値（`inning` / `half` / `team` / `runsScored` / `outsInPlay`）が**入力時の値で凍結保存**され、再計算で更新されない
  → 過去イベントの編集・削除でイニングスコアと打順表が実際の進行と乖離する（game-reducer.ts:65-103）
- 得点集計が二重基準：チーム得点は凍結値 `runsScored`、個人成績は `runnerMovements` を無条件カウント
  → 3アウト目と同時のホームインで**チーム合計と個人合計が合わない**（game-utils.ts:540 vs :593-609）
- `getEffectiveTotalInnings` が現在イニングを最大値に含めるため、**ビジター勝利・延長決着で試合が自動終了しない**（game-utils.ts:64, :939-960 の判定が事実上デッドコード）
- 走者の重複バリデーションがなく、野選・打撃妨害で一塁走者が**盤面から消える**（game-utils.ts:338-345, :462）
- `game-utils.ts`（960行）にルールエンジン・再生・統計・表示フォーマット・UI セレクタの6責務が混在
- 打点等の構造化データを `"右安·打点1"` のような**自由テキストに退化させ、正規表現で再パース**している
- **テスト0件**（AGENTS.md は TDD/vitest を指示しているが、vitest 自体が未導入）

### 主な機能ギャップ（PRD 比・野球ルール比）

- イニング数設定（PRD 1.2）が未実装 — `totalInnings: 9` ハードコード。**7回制の草野球が記録できない**
- 振り逃げが入力不可能（三振は強制アウト＋進塁シートスキップ）
- 犠飛と犠打の区別がなく、犠飛の既定進塁が誤り
- 併殺は「打者＋一塁走者」の1パターンのみ
- 代打・代走・投手交代・守備変更の概念が型にも UI にもない
- コールドゲーム未対応
- 走塁イベントが1走者固定（ダブルスチール不可）、走塁イベントの編集 UI は削除のみ
- 試合中画面に Undo ボタンがない（修正は打順表のセルを探して操作するしかない）
- localStorage にスキーマバージョン／マイグレーション機構がない

（詳細なバグ・ギャップ一覧は付録 A を参照）

## 2. 方針判断: 全面作り直しではなく「ドメイン層の再構築 + UI の流用」

| 選択肢 | 判断 |
|---|---|
| A. 現行コードにパッチを重ねる | ❌ バグの多くが「導出値の凍結保存」という設計に起因し、個別修正では再発する |
| B. リポジトリごと作り直す | ❌ UI・モバイル対応・記法ロジックという最大の資産を捨てることになる |
| **C. lib/ を TDD で再設計し、components/ は新ドメイン API に順次つなぎ替える** | ✅ **採用**。バグの根を断ちつつ資産を活かせる。テストが先にできるため移行の安全網にもなる |

方針 C の核となる設計判断:

1. **イベント＝入力のみ**。`GameEvent` が持つのは「誰が・どんな結果で・走者がどう動いたか」だけ。
   イニング・表裏・アウト・得点・打点集計は**すべて replay（先頭からの再生）で導出**する。
   → 編集・削除・挿入がどこで起きても整合性が自動的に保たれる（PRD 4.1 の再計算要求を構造で満たす）。
2. **ドメイン層は純関数のみ**（React・localStorage 非依存）。TDD が容易になり、AGENTS.md の方針とも一致。
3. **規定イニング数と到達イニング数を別概念にする**。試合終了判定のバグの根本原因を除去。
4. **走者の重複・3アウト整合などの不変条件を replay 内で検証**し、違反時は入力を拒否 or 警告を返す。
5. **表記（スコアブック記法）は構造化データから一方向に生成**。自由テキストの再パースを廃止。

## 3. 目標アーキテクチャ

```
lib/
├─ domain/
│   ├─ types.ts        // Game, Team, Player, GameEvent(入力のみ), Snapshot(導出状態)
│   ├─ rules.ts        // 既定進塁の提案、進塁の妥当性検証（純関数）
│   ├─ replay.ts       // events[] → Snapshot / タイムライン（イニング区切り・得点・成績を一括導出）
│   ├─ stats.ts        // 個人・チーム成績（replay の結果からのみ計算）
│   └─ notation.ts     // スコアブック表記の生成（"遊ゴロ" "盗2" 等）※逆パースはしない
├─ storage/
│   └─ local-storage.ts // schemaVersion 付き保存・読込・旧データのマイグレーション
└─ app-state/
    └─ game-context.tsx // useReducer + Provider（アクションは domain 関数の薄いラッパー）
```

### イベントスキーマ v2（要点）

```ts
// イベントは「入力」だけを持つ。位置づけ（何回の表か等）は replay が決める。
type GameEvent =
  | { id; kind: "atBat"; batterId; result: AtBatResult;
      battedBall?: { position: FieldingPosition; type: "ground" | "fly" | "liner" | "bunt" };
      movements: RunnerMovement[] }          // 打者含む全走者の移動。RBI フラグ付き
  | { id; kind: "baseRunning"; type: BaseRunningType;
      movements: RunnerMovement[] }          // 複数走者可（ダブルスチール対応）
  | { id; kind: "substitution";              // 代打・代走・守備交代・投手交代（Phase 3）
      team; inPlayerId; outPlayerId; role: "pinchHitter" | "pinchRunner" | "fielder" | "pitcher" }
  | { id; kind: "gameControl";               // コールド・没収など手動の試合制御
      action: "endGame"; reason?: string };
```

- `result` に `uncaughtThirdStrike`（振り逃げ）、`sacrificeFly`（犠飛）を追加し、`sacrifice` は犠打専用にする。
- 併殺・三重殺は専用 result をやめ、「movements 内のアウト数」から導出する（2-6-3 等の任意パターンに対応）。
- 打点は `RunnerMovement.isRBI` に一本化。`resultDetail` への埋め込み文字列（"·打点1"）は廃止。
- 保存データに `schemaVersion` を付与し、現行データ（v1）からのマイグレータを用意する。

### Replay（再生）の責務

`replay(events, config) => { snapshot, timeline, violations }`

- snapshot: 現在のイニング・表裏・アウト・走者・次打者
- timeline: イベントごとに「何回の表裏で起きたか・得点・アウト」を付与した列（スコアボード・打順表・成績はすべてここから描画）
- violations: 走者重複・アウト超過などの不変条件違反（編集時の警告表示に使用）

## 付録 C: 実装検証の結果（2026-07-26）

検証方法: `pnpm test`（11 ファイル 91 件 green）・`pnpm exec tsc --noEmit`・`pnpm build` を実行の上、全フェーズ項目をコード読解で照合。実機（ブラウザ）での通し確認は未実施。

### C-1. 残存バグ（機能に影響。優先的に対応）

1. **振り逃げの進塁が既定値に固定される**: `isAutoAdvanceAtBatResult`（game-utils.ts）が `uncaughtThirdStrike` を自動確定扱いにするため進塁シートが開かない。振り逃げ失敗（捕手→一塁アウト）や他走者の進塁を入力できない。
2. **編集時に打点フラグが失われる**: `runner-advance-sheet.tsx:143-149` が `initialMovements` の `isRBI` を読まず `defaultRbiWhenScoring` で作り直すため、「打点に含めない」と手動指定した打席を再編集すると既定値に戻る（付録 A-f の未解消分）。
3. **violations が UI に一切表示されない**: replay は不変条件違反を返し `AppGame.violations` まで運ばれているが、UI での参照が 0 件。違反イベントは `applied:false` で盤面から静かに消えるため、「記録しました」トーストが出るのに反映されない無言の失敗が起こりうる。
4. **フォースアウトで3アウト目が成立するケースの得点計上に疑義**: replay の3アウト同時得点判定は「打者がアウトの場合」と movements の配列順に依存しており、走者の封殺で3アウト目になった場合、配列上それより前の本塁到達が得点として残る可能性（実ルールでは無得点）。テスト未カバー。

### C-2. ドメイン層の設計残課題
