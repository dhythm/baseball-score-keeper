# 野球スコアラー PRD（プロダクト要求定義書）

## プロダクト名（仮）

**スコアブック** — 草野球対応リアルタイムスコアリングアプリ

## 概要

試合中にベンチからリアルタイムでスコアをつけられるWebアプリケーション。草野球の柔軟な人数構成（9人未満・10人以上の全員打ち）に対応しつつ、3アウトチェンジなどの基本ルールは厳守する。入力ミスは後から修正可能。

## ターゲットユーザー

- 草野球チームのスコアラー（ベンチでスマホ or タブレットから入力）
- 試合中のリアルタイム入力がメインユースケース

## ゴール

1. **試合中にライブでスコアをつけられる** — 打席結果を1つずつ入力し、得点・アウトが自動計算される
2. **ランナー状況が一目でわかる** — ダイヤモンドUIで塁上のランナーを常に表示
3. **後から修正できる** — 入力ミスがあった場合、過去の打席結果を編集して整合性を再計算
4. **草野球の柔軟な人数に対応** — 打順は9人に限定せず、任意の人数で設定可能

## コア機能

### 1. 試合セットアップ

#### 1.1 チーム設定

- 2チーム（先攻・後攻）を設定
- 各チームのチーム名を入力
- 各チームの打順（選手リスト）を設定
  - 選手名を入力して打順に追加
  - 打順の並び替え可能
  - **人数制限なし**: 7人〜15人以上でも設定可能（全員打ちに対応）
  - 最低人数のバリデーションは設けない（草野球の柔軟性を尊重）

#### 1.2 イニング設定

- デフォルト: 7イニング（草野球標準）
- 変更可能: 5, 7, 9 イニングから選択、またはカスタム値
- 延長イニングへの対応（試合中に追加可能）

### 2. ライブスコアリング（メイン機能）

#### 2.1 現在の打席表示

- **現在の状態を常に表示**: イニング数、表/裏、アウトカウント、得点
- **現在のバッター**: 名前を大きく表示、打順内の位置がわかる
- **ランナー表示**: ダイヤモンド型UIで1塁・2塁・3塁のランナーを表示（選手名付き）
- **次のバッターのプレビュー**: 打順の次の選手を小さく表示

#### 2.2 打席結果の入力

打席結果を選択式で入力する。選択後、ランナーの進塁・得点を処理する。

**打席結果の種類:**

| カテゴリ   | 結果                 | 説明                                         |
| ---------- | -------------------- | -------------------------------------------- |
| **安打**   | シングルヒット       | 打者→1塁。ランナー進塁を確認                 |
|            | ツーベースヒット     | 打者→2塁。ランナー進塁を確認                 |
|            | スリーベースヒット   | 打者→3塁。ランナー進塁を確認                 |
|            | ホームラン           | 打者＋全ランナー生還                         |
| **アウト** | ゴロアウト           | アウト+1。ランナー進塁を確認                 |
|            | フライアウト         | アウト+1。ランナー進塁を確認（犠牲フライ等） |
|            | 三振                 | アウト+1。ランナー変動なし（基本）           |
|            | 併殺打               | アウト+2。ランナー状況に応じて処理           |
|            | その他アウト         | アウト+1〜。自由入力メモ付き                 |
| **四死球** | 四球（フォアボール） | 打者→1塁。押し出し判定あり                   |
|            | 死球（デッドボール） | 打者→1塁。押し出し判定あり                   |
| **エラー** | エラー出塁           | 打者→1塁（デフォルト）。ランナー進塁を確認   |
| **その他** | 犠打（バント）       | アウト+1。ランナー進塁を確認                 |
|            | フィルダースチョイス | 打者→1塁。アウト対象ランナーを選択           |
|            | 打撃妨害             | 打者→1塁                                     |

#### 2.3 ランナー進塁処理（重要）

打席結果の入力後、ランナーの進塁先を確定する。これが正確なスコアの要。

**自動進塁（確定処理）:**

- ホームラン → 全ランナー＋打者がホーム生還
- 四球/死球 → 押し出しの場合、強制進塁を自動処理
- 三振 → ランナー変動なし（デフォルト）

**手動進塁確認（打席結果入力後のサブステップ）:**
安打・ゴロアウト・フライアウト・エラーなど、ランナーの進塁が状況依存の場合：

1. 打席結果選択後、「ランナー進塁確認画面」を表示
2. 各ランナーの進塁先を選択（例: 2塁ランナー → 3塁 or ホーム or そのまま）
3. 確認して確定

**ランナー進塁確認UIの設計:**

- ダイヤモンドUIベースで操作
- 各ランナーの選択肢: 「そのまま」「次の塁へ」「2つ進塁」「ホーム生還」「アウト」
- 遠い塁のランナーから順に表示（3塁→2塁→1塁→打者）— **遠いランナーが上に来る**
- デフォルト進塁を自動セット（例: シングルヒットなら各ランナー+1塁をデフォルト提案）
- ユーザーが修正して確定

#### 2.4 アウトカウント管理

- 打席結果に応じてアウトカウントを自動加算
- **3アウトで自動的にチェンジ**（攻守交代）
  - 3アウト目の打席結果は記録するが、それ以上の入力は次のイニングへ
  - 3アウト時にランナーが残っていても自動クリア（残塁として記録）
- 併殺打で2アウト加算。2アウト時の併殺打は3アウトで切る（3アウト超過しない）

#### 2.5 イニング・攻守交代

- 3アウトで自動的に攻守交代
- 表→裏→次のイニング表... と進行
- 最終イニング裏で後攻がリードしている場合、裏の攻撃はスキップ可能（サヨナラ or 省略）
- 延長イニング追加ボタン

#### 2.6 盗塁・ワイルドピッチ等（打席外イベント）

打席結果とは別に、打席中に発生するイベントを記録できる。

- **盗塁**: ランナーを選択して進塁先を指定
- **盗塁死**: ランナーを選択してアウト（アウトカウント+1）
- **ワイルドピッチ / パスボール**: ランナーを選択して進塁
- **牽制アウト**: ランナーを選択してアウト（アウトカウント+1）
- **ボーク**: 全ランナー1つ進塁

これらは「打席中イベント」ボタンから入力し、打席結果とは独立して記録する。

### 3. スコアボード表示

#### 3.1 イニングスコアボード

- 横長のスコアボード（野球中継風）
- 各イニングの得点を表示
- 合計得点（R）、安打数（H）、エラー数（E）を表示
- 現在のイニングをハイライト

#### 3.2 試合サマリー

- 各チームの打撃成績一覧
  - 選手名、打数、安打数、打点、得点
- イニング別の詳細結果（打席結果の時系列）

### 4. 結果修正機能

#### 4.1 打席結果の修正

- イニング別の打席結果一覧を表示
- 任意の打席を選択して結果を修正
  - 打席結果の種類を変更
  - ランナー進塁を再設定
- **修正後の自動再計算**: 変更した打席以降の得点・アウト・ランナー状況を再計算
  - 再計算により整合性が崩れる場合（例: アウト数変更で以降の打席順が変わる）、警告を表示
  - 再計算の影響範囲をプレビュー表示

#### 4.2 修正の制約

- 打席結果の変更は可能だが、打席の追加・削除は慎重に扱う
  - **追加**: 漏れていた打席を挿入（例: 盗塁死の記録漏れ）
  - **削除**: 誤って入力した打席を削除（以降を再計算）
- 再計算で3アウトの整合性が崩れる場合は、ユーザーに確認を求める

### 5. データ保存

#### 5.1 ローカルストレージ

- 試合データはブラウザのlocalStorageに自動保存
- 打席結果を入力するたびに自動保存（入力漏れ防止）
- アプリを閉じても試合データが残る
- 試合完了後もデータは保持（明示的に削除するまで）

#### 5.2 保存データ構造

- 試合メタ情報（日付、チーム名、イニング数）
- 打順データ（各チームの選手リスト）
- 全打席結果の時系列データ（イニング、打席番号、結果、ランナー進塁）
- 打席外イベント（盗塁等）

## データモデル（概念設計）

### Game（試合）

```
{
  id: string,
  date: string,
  totalInnings: number,           // 設定イニング数
  status: "setup" | "live" | "finished",
  teams: {
    away: Team,                    // 先攻
    home: Team                     // 後攻
  },
  currentState: {
    inning: number,                // 現在のイニング
    half: "top" | "bottom",        // 表 or 裏
    outs: number,                  // 現在のアウトカウント
    runners: {                     // 現在のランナー状況
      first: string | null,        // 1塁ランナーの選手ID
      second: string | null,       // 2塁ランナーの選手ID
      third: string | null         // 3塁ランナーの選手ID
    },
    currentBatterIndex: {          // 各チームの現在のバッターIndex
      away: number,
      home: number
    }
  },
  events: Event[]                  // 全イベント（時系列）
}
```

### Team（チーム）

```
{
  name: string,
  players: Player[]                // 打順順
}
```

### Player（選手）

```
{
  id: string,
  name: string,
  order: number                    // 打順番号（1〜）
}
```

### Event（イベント — 全打席結果・打席外イベントを時系列で保存）

```
{
  id: string,
  type: "atBat" | "baseRunning",   // 打席 or 打席外イベント
  inning: number,
  half: "top" | "bottom",
  team: "away" | "home",

  // 打席の場合
  batterId: string,
  result: AtBatResult,             // 打席結果の種類
  resultDetail?: string,           // 補足メモ（"ショートゴロ"等）

  // ランナー進塁結果
  runnerMovements: RunnerMovement[],

  // 打席外イベントの場合
  baseRunningType?: "steal" | "caughtStealing" | "wildPitch" |
                    "passedBall" | "pickOff" | "balk",

  // 計算結果（再計算用）
  outsInPlay: number,              // この打席で発生したアウト数
  runsScored: number,              // この打席で発生した得点数

  // メタ
  timestamp: string                // 入力時刻
}
```

### RunnerMovement（ランナー進塁）

```
{
  playerId: string,
  from: "batter" | "first" | "second" | "third",
  to: "first" | "second" | "third" | "home" | "out",
  isRBI: boolean                   // 打点としてカウントするか
}
```

### AtBatResult（打席結果の列挙）

```
"single" | "double" | "triple" | "homerun" |
"groundOut" | "flyOut" | "strikeout" | "doublePlay" | "otherOut" |
"walk" | "hitByPitch" |
"error" |
"sacrifice" | "fieldersChoice" | "interference"
```

## ルール・バリデーション

### 厳守するルール

1. **3アウトチェンジ**: アウトカウントが3になったら必ず攻守交代。超過しない
2. **併殺打のアウト上限**: 現在のアウト数 + 併殺のアウト数が3を超えない（例: 2アウトから併殺 → 3アウトで切る）
3. **ランナーの重複禁止**: 同じ塁に2人のランナーは存在できない
4. **得点の整合性**: ホームに到達したランナーのみ得点。3アウト目と同時にホームインしたランナーは得点にならない（ただし、3アウト目より前にホームインしたランナーは得点）
5. **打順の循環**: 打順はチームの選手リストを循環する（最後の打者の次は1番に戻る）

### 緩和するルール（草野球対応）

1. **人数制限なし**: 打順の人数は自由（全員打ちに対応）
2. **DH・守備位置の管理なし**: スコアリングに不要なため省略
3. **投手交代の記録なし**: MVP時点では不要
4. **ボールカウントの記録なし**: 結果のみ記録

## 成功指標

1. **試合をリアルタイムで最後までスコアリングできる**: セットアップ〜最終イニングまで一貫して入力可能
2. **1打席の入力が10秒以内**: 結果選択→ランナー確認→確定がスムーズ
3. **修正後の再計算が正確**: 過去の打席修正後、以降の得点・アウトが正しく再計算される
4. **3アウトの整合性が常に保たれる**: どのような修正を行っても3アウトチェンジは崩れない

## 補足: ステート管理の設計方針

試合の状態は**イベントソーシング**パターンで管理する。

- `events[]` 配列が唯一の真実のソース（Source of Truth）
- `currentState`（イニング、アウト、ランナー）は `events[]` から常に導出可能
- **修正**: `events[]` 内の該当イベントを書き換え → 先頭から再計算して `currentState` を再構築
- **利点**: データの整合性が保証される。修正しても全体が自動的に整合する

この設計により、「修正→再計算」が安全かつシンプルに実装できる。
