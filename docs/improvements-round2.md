## 2. A: まず仕上げ（第1弾の残り、費用対効果最大）

1. **シートスキップ条件の一般化**
   「既定 movements が打者のみ、かつ走者不在」の一般条件へ変更
   （`uncaughtThirdStrike` は打者アウト/出塁の分岐があるため明示除外）。
   走者なしの単打・内野安打・エラーの確定タップが消える。
2. **打球コンテキストの適用範囲拡大**
   `groundOut`（一塁走者の封殺既定・進塁打の既定提案）、`flyOut`（浅い/深いの
   タッチアップ）、`double`（外野方向なら一塁走者生還）、`error` へ
   `DefaultMovementContext` を適用。基盤配線は済んでいるため追加コストは小さい。
3. **ダブルスチールの既定進塁**
   走者 2 人以上の盗塁でも `getConventionalAdvanceDestination` を一括適用し、
   チェックした走者全員に既定進塁先を自動セット。

## 3. B: 試合中の信頼性（新規・重要）

4. **複数タブ/複数端末の同時編集ガード**
   localStorage への書き込みは最後勝ちで `storage` イベントの監視がない。
   試合中に誤って 2 タブで開くとイベントが黙って巻き戻る。
   `storage` イベントで他タブの更新を検知し、警告表示 or 読み取り専用化する。
5. **React Error Boundary**
   描画中の例外で試合中でも画面全体が落ちる。境界を設置し、
   「記録データは保存されています + JSON エクスポート」の退避画面を出すことで
   最悪時も記録を失わない。
6. **多段 Undo / スナップショット**
   Redo は 1 段・非永続（lib/app-state/reducer.ts:172-185）。イベントソーシングの
   利点を活かし、直近 N 操作の履歴スタック、「イニング開始時点に戻す」、
   削除イベントのゴミ箱（復元可能な論理削除）を安価に実装できる。
7. **Service Worker の更新フロー**
   キャッシュバージョンが手動管理（v5）で、新版デプロイ後も旧アプリシェルが
   残り続ける。「新しいバージョンがあります → 再読み込み」プロンプトと、
   ビルドハッシュ連動のキャッシュキーを導入する。
8. **保存失敗の検知**
   localStorage 書き込み失敗（容量超過・プライベートモード）時に常設バナーで
   「保存されていません」を表示。現状は握り潰しの可能性があるため要確認。

## 4. C: 入力 UX の次の一手

9. **ダイヤモンド図の直接操作**
   diamond-field.tsx は表示専用のまま。走者バッジをタップ → 盗塁/進塁/アウトを
   選ぶ導線は最短の走塁入力になる（現行の走塁シートは残しつつ入口を追加）。
10. **打順表の縦方向の自動追従**
    横（イニング列）の自動スクロールは実装済みだが、現在打者の行への
    縦スクロールは未実装。
11. **屋外モード**
    ベンチは直射日光下。ハイコントラスト配色と文字サイズ拡大の切替（設定 1 箇所）。
    確定時の振動フィードバック（`navigator.vibrate`）で画面を見続けなくてよくなる。
12. **試合履歴の上限緩和**
    現状 10 件固定。使い込むと溢れるため、容量ベースの上限へ引き上げ、
    溢れ時は古い試合を自動 JSON 書き出しして退避する。

## 5. D: スコアブックとしての拡張（DB 接続前でも可能）

13. **チーム集計の拡充**
    盗塁数・残塁（LOB）・失策の詳細・チェンジごとの残塁表示。
    データは timeline に揃っているため集計関数の追加のみで実現できる。
14. **紙スコアブック風の出力**
    現状の共有はテキスト/JSON のみ。打順×イニング表を画像（canvas）や
    印刷用 CSS で書き出せると、チーム LINE 等への共有が実運用に乗る。
15. **選手の試合間通算**
    localStorage の履歴を跨いだ通算打率・出塁率の計算。
    選手名の名寄せ（チームテンプレート）とセットで導入する。
